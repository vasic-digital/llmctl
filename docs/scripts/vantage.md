# llmctl-decide vantage (second network location, FR-064/FR-069/FR-073)

Boots a tiny rootless container through the Containers submodule
(`digital.vasic.containers/pkg/runtime`) that has its own address, so the
transport tests can call the gateway from a network location other than the
host loopback. Implementation: `internal/vantage/`; subcommand registered in
`cmd/llmctl-decide/cmd_vantage.go`; real test: `tests/test_vantage.sh`.

```
llmctl-decide vantage up [--network slirp4netns|bridge] [--image IMG] [--probe-bin F] [--host-ip IP]
llmctl-decide vantage status | down | selfcheck          # also: vantage --selfcheck
llmctl-decide vantage exec -- ARGV...
llmctl-decide vantage probe --url URL [--cacert F] [--expect-status N] [--expect-tls-failure]
                            [--method M] [--header Name:Value]... [--body S] [--timeout D]
llmctl-decide vantage probe-ports --host-ip IP --ports a,b,c
```

State: `$LLMCTL_STATE_DIR/vantage/state.json` (name, id, image, network, ip,
gateway, host_ip). Exit codes: 0 ok, 1 failure, 2 usage, 3 rootless containers
unavailable (reason on stderr; callers may skip, never pass).

Network mode (measured on this host, rootless podman 5.x): `slirp4netns` and the
default netavark `bridge` give a distinct address and distinguish a
127.0.0.1-only listener from a 0.0.0.0 one; `pasta` (the rootless default) does
not (it copies the host address) and is refused. Limits: slirp traffic is
generated by a host process, so it does not exercise the host firewall's inbound
rules, the router, NAT, DDNS or the ISP (FR-065 items stay "not provable here").

## Ownership and secrecy (C-07, C-15, C-16)

* **Owner label.** Every container carries `llmctl.vantage.owner=<sha256(abs state dir)[:12]>`; `vantage down`
  removes only containers with its own owner label (plus the one recorded in its state file), so two state
  dirs on one host never remove each other's vantage. `vantage down --all` additionally removes every
  `llmctl-vantage-*` container of any owner (recovery after a lost state dir).
* **State files.** `down` deletes only the files it wrote (`state.json`, `state.json.tmp`, the staged probe,
  request files) and removes the directories only when that leaves them empty - it never `RemoveAll`s
  `<state>/vantage`, so `--state-dir ~` cannot delete an unrelated `~/vantage`.
* **Probe secrets.** Headers and body of `vantage probe` do not travel on the `podman exec` argv (visible in
  `ps`): they are written as 0600 JSON into the bind-mounted probe dir and passed with
  `vantage-probe http --request-file /vantage/req-<random>.json`; the file is removed when the call returns.

## Prerequisite: one locally cached image (G-085)

`vantage up` is offline: it starts the probe with `--pull=never`, so ONE of the candidate images must already be
in the local rootless store (`podman images`). Candidates, tried in order: `$LLMCTL_VANTAGE_IMAGE`,
`gcr.io/distroless/static-debian12:nonroot`, `docker.io/library/alpine:3.20`, `alpine:3.19`, `alpine:latest`,
`debian:trixie-slim`, `ubuntu:24.04`. If none is cached, `up` exits 1 with `no usable local image`; llmctl never
pulls one for you. To provide one (operator action, needs network once):

```bash
podman pull docker.io/library/alpine:3.20     # or: export LLMCTL_VANTAGE_IMAGE=<any image already cached>
```

`tests/test_vantage.sh` treats exactly this case as a missing prerequisite: it prints
`SKIP-SUITE: rootless podman works but no candidate image is cached locally ...; tried: <images>; fix: podman pull ...`
(shown by `tests/run_tests.sh` as a SKIP, never a pass) and any other `up` failure stays a FAIL. Proven by running the
suite against an empty image store (`CONTAINERS_STORAGE_CONF` pointing at a fresh graphroot) and by the classifier
self-check at the top of the suite.
