## New Files This Plan Introduces (US7-9 — `llmctld` cluster daemon)

No plan.md design existed for the cluster daemon before this tasks.md; the layout, dependency choices, and interfaces below are locked in here so tasks can be written without placeholders.

**Go module**: `llmctld/` (new top-level directory, sibling to `bin/`, `lib/`), module path `github.com/vasic-digital/llmctl/llmctld`, Go 1.26 (matches the toolchain already on this host).

**Chosen dependencies** (fetched and verified present in the local Go module cache 2026-09-15 via `go get <pkg>@latest`; exact versions resolved at that time — `go.mod` itself stays free of `require` lines until Phase 2+ code actually imports each one, since `go mod tidy` correctly prunes unused requires from a stub-only module — this is expected Go tooling behavior, not a gap):
- `github.com/hashicorp/raft` **v1.7.3** — embedded Raft consensus (Clarification 10)
- `github.com/hashicorp/raft-boltdb/v2` **v2.3.1** + `go.etcd.io/bbolt` **v1.5.0** — Raft log/stable/snapshot store and general node-local persistent storage (WAL, checkpoints)
- `github.com/gin-gonic/gin` **v1.12.0** — HTTP handler/routing (Clarification 9)
- `github.com/quic-go/quic-go` **v0.62.0** (`.../http3` subpackage) — HTTP/3 (QUIC) server; the same `gin.Engine` (implements `http.Handler`) is also served over plain `net/http` + TLS (ALPN `h2`) as a fallback, because this host's `curl 8.18.0` reports `Features: ... HTTP2 ...` with **no HTTP3** — a real, verified environmental constraint (not every client `llmctl` talks to will have an HTTP/3-capable libcurl), so `llmctld` MUST dual-stack: HTTP/3 primary via UDP/QUIC, HTTP/2 fallback via TCP/TLS on the same routes, advertised via `Alt-Svc`.
- `github.com/andybalholm/brotli` **v1.2.4** — response compression; wrapped in a small custom Gin middleware (`internal/api/middleware_compress.go`) rather than a third-party Gin-brotli micro-package, to avoid an unmaintained-dependency risk
- `github.com/golang-jwt/jwt/v5` **v5.3.1** — JWT issuance/validation
- `github.com/coreos/go-oidc/v3` **v3.21.0** — optional OIDC integration
- `github.com/google/uuid` **v1.6.0** — entity IDs
- `github.com/stretchr/testify` **v1.12.1** — test assertions (unit tests only, per Constitution §11.4.27 — integration tests use real processes, no mocks)
- `crypto/tls` + `crypto/x509` (stdlib) — internal CA + mutual TLS cert issuance for node-to-node traffic
- `log/slog` (stdlib) — structured logging, JSON audit-log-adjacent event stream

**Bash-side additions** (calling into `llmctld` when cluster mode is enabled):
- `lib/cluster.sh` — new module: `cluster::request <method> <path> [json-body]` wraps `curl` (HTTP/2 baseline; opportunistically `--http3` when the local curl build supports it, detected once by `doctor.sh`); hard-fails per Clarification 12 when the daemon is unreachable — **never** falls back to single-host scheduling.
- `bin/llmctl` — new `cluster <join|leave|status>`, `tenant <create|list|quota>`, `apikey <create|rotate>` subcommands under a new "CLUSTER (opt-in, requires llmctld)" usage() section.
- `lib/service_linux.sh` / `lib/service_macos.sh` — extended with an `llmctld` systemd --user unit / launchd plist template (installed via `llmctl cluster enable`).
- `lib/doctor.sh` — extended with a curl-HTTP/3-capability probe and a `go version` check (needed only when cluster mode is used).

**New Makefile targets**: `llmctld-build`, `llmctld-test`, `llmctld-lint` (guarded with the same "if command -v golangci-lint" pattern the existing `lint` target uses for shellcheck — `golangci-lint` is not installed on this host today), wired into `validate` only when `LLMCTL_CLUSTER_MODE=1` is set (single-host `make validate` stays bash-only and fast, per the "single-host mode untouched" decision).

## Follow-up Work (post-completion, beyond the original 89-task/12-phase plan)
