# Containers submodule gaps found while building `internal/registry` (T069, T076)

Pinned commit `4a8f04e05f3535d77c48f69b89687f9fcc896fbf`. Per FR-091 these are **upstream extension items**
(the submodule was not edited); `internal/registry` works around each one locally and says so in its code.
Status "worked around" = behaviour proven by tests in `internal/registry`; the workaround is meant to be deleted
when the upstream item lands.

| # | Package | Gap (measured by reading the code and by tests) | llmctl workaround | Proposed upstream change |
|---|---|---|---|---|
| G1 | `serviceregistry` | Not safe across **processes**: `New()` loads `services.json` once; `persist()` rewrites the whole in-memory map, so two processes silently lose each other's updates (test `TestConcurrentRegistersFromProcessesAndGoroutines`; mutation "no cross-process lock" makes it fail). No `Reload()`. | `withLock` (flock) around every operation + a fresh handle per operation (`internal/registry/lock.go`) | `WithFileLock()` option (flock around load-modify-persist) and `Reload()` |
| G2 | `serviceregistry` | `New()` -> `reapOrphanedTempFiles()` deletes **every** `services-*.json.tmp`, including another live process's in-flight temp file between `CreateTemp` and `Rename` -> that writer's `Register` fails. | all handles are created under the lock (readers shared, writers exclusive), so no reaper ever overlaps a writer | reap only temps older than a threshold, or hold the lock while reaping |
| G3 | `serviceregistry` | A corrupt `services.json` is moved aside and the registry continues **empty**; `New()` returns no error, only an `Error()` log line - indistinguishable from "no services". | custom `Logger` captures `Error()` during load and `open()` turns it into an error (`TestOrphanTempFilesAndCorruptFile`) | `NewE(...) (*ServiceRegistry, error)` or `LoadErr()` |
| G4 | `serviceregistry` | `Service` has no pid, start time, command identity, loopback flag or unhealthy-since; no way to update labels without re-`Register`. | packed into `Labels` under the reserved `llmctl.` prefix and stripped on read (`registry.go`) | typed `PID`/`Started` fields or a `Metadata` map; `UpdateLabels(name, ...)` |
| G5 | `serviceregistry` | No liveness proof and no expiry: `Healthy` is a bool the caller sets; an entry for a SIGKILLed process stays forever. | `Registry.Reconcile` (process identity from `/proc/<pid>/cmdline` + `pkg/health` probe + grace) | a reaper / TTL with a pluggable liveness probe |
| G6 | `serviceregistry` | No change notification and no label-selector query. | `Registry.Watch` (stat identity + content digest of the routable view) and `Registry.Resolve(labels)` | `Watch(ctx) <-chan Event`, `Select(labels)` |
| G7 | `serviceregistry` | `Register` refuses a host:port held by another name even if that holder is dead (correct as a collision rule, but permanently blocks a restart on the same port until someone unregisters). | `Register` reaps a same-port holder whose process identity check fails, refuses a live one | optional liveness callback on collision |
| G8 | `network` | `PortAllocator` is in-memory only: no persistence, no cross-process exclusion, no lookup/release by name, no sticky reuse. Two processes each construct their own allocator and can hand out the same port before either service binds. | durable `ports.json` under flock; `MarkAllocated` of every other service's hold before each `Allocate`; sticky hint map (`ports.go`); proven by `TestConcurrentAllocateAcrossProcesses` (8 real processes x 5 rounds) | persistent allocator with a pluggable store and named allocations |
| G9 | `network` | `isPortAvailable` tests **127.0.0.1 only**. A listener bound to a specific non-loopback address (e.g. `192.168.x.y:P`) does not conflict with the 127.0.0.1 test, so such a port can be handed out then fail at bind time for a service that binds `0.0.0.0`. (A `0.0.0.0` or `127.0.0.1` listener is detected.) | `registry.bindTest` also binds 0.0.0.0, :: and every local interface address, and the range walk bind-tests each candidate (W3, 2026-10-07); patch text `containers-upstream/G9-network-bind-all-addresses.md` | test wildcard as well as loopback, make the bind address configurable |
| G10 | `health` | `CheckHTTP` builds a client with the default TLS config: no CA pool / `InsecureSkipVerify` / client cert, so a service behind llmctl's **own CA** (the gateway) cannot be HTTP-probed; scheme is hard-coded `http` when `URL` is empty. | https entries: `registry.TLSCheck` - TLS handshake verified against the llmctl CA + GET of the health path (W3, 2026-10-07); patch text `containers-upstream/G10-health-tls-config.md` | `HealthTarget.TLSConfig *tls.Config` (or `HTTPClient`) |
| G11 | `endpoint` | The package cannot be imported by this repo: it needs `gopkg.in/yaml.v3`, which `go.mod` does not require (go.sum already has the hashes), so `go build` says "updates to go.mod needed". Verified that adding `require gopkg.in/yaml.v3 v3.0.1 // indirect` fixes it (checked with `-modfile`, go.mod untouched). | `Entry.URL()` reproduces `ResolvedURL` for the two schemes (`types.go`) | **DONE (2026-10-07): `go.mod` requires yaml.v3; `Entry.URL` now calls `endpoint.NewEndpoint()...ResolvedURL()`** |
| G12 | `serviceregistry` | Registry directory is created `0755` by `persist()` (world-listable service map). | the directory is created `0700` first by `withLock` | `WithDirMode` option |
| G13 | `discovery` | Not used: it discovers *external* endpoints by DNS/TCP probing; llmctl's discovery is the registry itself (FR-089/090). | n/a | n/a |
